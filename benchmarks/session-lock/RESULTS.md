# Session lock: Rust vs ckb-js-vm

Generated by `npm run bench:session-lock`. Both implementations run the same
20 scenarios in the real CKB-VM (ckb-testtool + ckb-debugger) and
**agree on every accept/reject decision**.

| | Rust | ckb-js-vm |
|---|---:|---:|
| Code deployed | 4,344 B binary | 29,118 B bytecode + 410,248 B VM |
| Mean cycles, accepted spends | 12,263 | 14,573,318 |
| Median ratio, all scenarios | 1× | 2027× |
| Cheapest run (bad args: start-up cost) | 2,318 | 13,916,789 |

**Where the ckb-js-vm cycles go.** The cheapest run — args rejected almost
immediately — still costs 13,916,789 cycles: that is the price of starting
the JavaScript VM and loading the bytecode. An accepted spend averages
14,573,318, so the lock's own logic is only about 656,529 of it
(5%). For a script this small, ckb-js-vm's cost is almost
entirely fixed start-up, and the logic itself runs at roughly
66× the Rust logic's cycles.
